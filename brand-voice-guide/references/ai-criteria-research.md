# AI selection-criteria research

This step finds two things: what the AI engines tell shoppers to check when choosing this kind of business in this place, and what they ask the shopper. It feeds the proof map with real facts to surface. It doesn't set the voice.

It is not a ranking check. Never record who ranked where, which business came first, or whether the client appeared. Other businesses' names matter only for the kinds of facts the engines repeated about them.

## Set up

- **The query.** Take the main service and city from intake, phrased the way a shopper would type them. For example: `DUI lawyer [City]`, `plumber [City]`, `med spa [City]`. For a business that travels or runs events with no fixed city, use the city or metro of the next event, or the one that covers the likely venues, and log why. Don't put an unsettled fact (an age group, a gender, a price) in the query. For an organization with several programs, run the main program; add a second query only if a second program has a different shopper.
- **The engines.** ChatGPT with search on, Perplexity, Google AI Mode, and Gemini where you have it. Also check whether Google shows an AI Overview on the normal results page.
- **A fresh session every run.** Use a temporary chat, or sign out and use a private window. Turn memory and history off where the engine allows it. Log anything you couldn't control, such as having to stay signed in.
- **Where you're searching from.** Log your location. If you use an API instead of the app, log that, and the location setting if it has one, and save the raw response. API answers can differ from what the app shows.

## Three ways to run it (the skill always asks first)

**1. DataForSEO API.** Checked against docs.dataforseo.com on 2026-10-23.
- **Endpoints.** LLM Responses Live: `POST https://api.dataforseo.com/v3/ai_optimization/chat_gpt/llm_responses/live`, with `gemini` or `perplexity` in place of `chat_gpt`. Docs: https://docs.dataforseo.com/v3/ai_optimization-llm_responses-overview/.
- **Auth.** HTTP Basic with the API login and API password from https://app.dataforseo.com/api-access. The API password is generated by DataForSEO and is not the account password. Read it from DataForSEO's MCP server or the `DATAFORSEO_USERNAME` and `DATAFORSEO_PASSWORD` environment variables. Never ask for it in chat.
- **Required fields.** Every call needs `user_prompt` (500 characters max) and `model_name`. List the models first: each engine's `llm_responses/models` endpoint is free.
- **Model choice.** Pick the model closest to what a shopper gets in the free app, and use the same one for every run. In our test run, `gpt-5.4-mini` for ChatGPT and `sonar` for Perplexity did the job. Most ChatGPT models listed are reasoning models: they ignore `temperature`, and `force_web_search` may not apply. Log the exact model name each response reports.
- **Web search.** Set `web_search: true` for ChatGPT and Gemini. It defaults to off, and without it the answer comes from the model's memory and cites nothing (`annotations` comes back null). Perplexity's sonar models search by default.
- **Location.** ChatGPT takes `web_search_country_iso_code` and `web_search_city`; set the client's country and city. Perplexity takes the country code only. Gemini has no location setting. Log what you set.
- **History.** For turns 2 to 5, send the earlier turns in `message_chain`: roles `user` and `ai`, alternating (Perplexity requires it), up to 10 messages of 500 characters each. A five-turn run needs 8 by turn 5, so it fits. Most answers run longer than 500 characters, so shorten each earlier answer to fit and keep the businesses and criteria it named. Save the full answer in the raw file and log "history shortened".
- **MCP server.** If you use DataForSEO's MCP server instead of direct calls, check that its tool lets you set `web_search` and the message history. If it doesn't, say so before running.
- **Cost.** $0.0006 per Live task plus the model's own charge. Log the task-level `cost` from each response (it includes the fee; the result's `money_spent` doesn't), one line per call in `raw/cost-log.jsonl`. Real costs from our test run, 2026-10-23: ChatGPT `gpt-5.4-mini` $0.006 to $0.031 per call, about $0.10 per five-turn run; Perplexity `sonar` about $0.006 per call, about $0.03 per run; the minimum set plus two AI Overview checks came to $0.32. Make one test call per engine, multiply its real cost by the calls planned, and get a yes before the rest. If the user already set a budget ceiling, check the projection against it and say so instead of asking again. DataForSEO's free Sandbox works for a no-cost dry run of the requests.
- **AI Overviews and AI Mode** aren't in the LLM Responses endpoints. They come from DataForSEO's SERP API: Google Organic Live Advanced with `load_async_ai_overview: true` (a small extra charge), and `serp/google/ai_mode/live/advanced`, both with a location setting. Those responses also carry organic rankings, so save only the AI element. Or check them with option 2 or 3.
- **Errors are billed and aren't results.** A SERP call can return an error such as 40101 ("Internal SE Server Error") and still be billed (about $0.002 in our test). Log it as an error with its code and cost, retry once, and if it fails again write "not checked: API error 40101". Never log an error as "no AI Overview shown".
- **The GBP check.** DataForSEO's Google Maps endpoint can also answer whether the business has a Google Business Profile (about $0.002 a call), if the plain fetch comes back empty.
- **Variation.** Answers vary from run to run, which is why the set has more than one run. Save every raw response.

**2. Browser.** Run the five turns in the real apps with a fresh or temporary session each run. Include the AI Overview check on the normal Google results page. Log whether you were signed in. Only use tabs you opened. If a CAPTCHA, login wall or bot check appears, stop and offer option 3 rather than retrying in a loop.

**3. Guided prompts.** Default to the minimum set (2 engines, 2 runs each, plus one "how do I choose" chat per engine), unless the user asks for more. Give the user a numbered checklist: which engine, open a fresh or temporary chat, paste turn 1, wait, paste turn 2, and so on. Ask them to paste back the full text of every turn, plus the header details below (engine and mode, signed in, memory, location, date and time). Never fill in a turn they didn't paste.

Whichever method, the rest of this file applies: same prompts, same run counts, same logging.

## The run: one fresh conversation, five turns

1. `[service] [city]`
2. `best [service] in [city]`
3. `Why did you pick these? What credentials, certifications, trainings, specialties, education, awards or experience made them stand out?` (This names the categories, so it shows what the engine tells shoppers to check. The "how do I choose" conversation below is the neutral version.)
4. `What would make you recommend someone else instead?`
5. Answer the engine's first clarifying question with the most common situation for this business, in a few words (in a DUI test run: `First DUI.`). Then save the new questions it asks.
   **If it asked no question** (some engines never do, or only offer a menu like "I can narrow this down by..."), send this instead: `What should I ask a [service] before I choose one?` Log "turn 5: no clarifying question, fallback used". Don't answer a menu item as if it were a question, because it steers every run the same way and inflates those counts.

Once per engine, also open a separate fresh conversation and ask `how do I choose a [service] in [city]`. This asks for the criteria directly, before the engine has named anyone or heard our categories.

**AI Overviews take no follow-ups.** Search the turn 1 and turn 2 queries on the normal Google results page, then save the Overview text and its cited links. If no Overview shows, log "no AI Overview shown" as the result. Don't swap in AI Mode for a missing Overview; AI Mode is its own engine.

## Run counts

- **Standard:** 2 or 3 fresh runs on each engine you have, plus one "how do I choose" conversation per engine.
- **Minimum:** 2 runs on each of 2 engines. Below that, treat what you collected as anecdotes, not a pattern.
- **Time:** one five-turn run took about 5 minutes in our first test. At that pace a standard set takes 30 to 75 minutes by hand.
- **Read the counts as rough signals.** They describe your sample, not the engine. Report "n of N runs", never percentages.
- **State the coverage.** List what you ran at the top of the summary.

## Saving each run

Save one file per run: `research/ai-criteria/raw/<engine>-<n>-<YYYY-MM-DD>.md`.

Put this header at the top:
- Engine and mode (for example: ChatGPT, search on, temporary chat; or DataForSEO, model name, web search on, history shortened)
- Signed in: yes or no. Memory or history: on, off or unknown
- Model, if one is shown
- Where you searched from, or the location setting
- Date and time of the first prompt, with time zone
- The prompts, in order

Then paste the full text of every answer, word for word, with clarifying-question buttons as plain lines, followed by every cited link. Never edit a raw file after saving it, and never replace it with a summary. Raw files keep the engines' punctuation, dashes included; house style applies only to files we write.

Raw files keep other businesses' names because they're word for word. Keep the files inside your team. The summary and the guide never name other businesses.

## What to capture

Read every raw file, then fill in `research/ai-criteria/summary.md`.

**(a) Criteria.** Every reason an engine gave for picking someone, or for picking someone else instead. Group them by kind:
- Licenses and certifications
- Training (courses, and manufacturer or method training)
- Specialties and focus (how much of the work is this exact service)
- Education
- Awards, ratings and recognition
- Affiliations and memberships
- Local experience (courts, neighborhoods, local codes)
- Years doing this exact work
- How the work gets done (who does it, how fast, how they communicate)
- Price and terms (consultations, estimates, fees)
- Reviews and reputation
- Results and track record

For each criterion, count how many runs mentioned it at least once, add one verbatim example with the run file it came from, and mark whether it came up in the neutral "how do I choose" chat. Criteria named there, before we named any categories, are the stronger signal.

**Distinctions the engines drew.** Also log any distinction an engine made between credentials that look alike. In our DUI test run, the engine said belonging to a DUI defense association is not proof of certification, and that directory awards, DUI training and specialist certification are not interchangeable. These distinctions show you which upgrades the copy must never make.

**(b) Shopper questions.** These come in two kinds:
- **Situation:** what the engine asked the shopper. In our DUI test run, these included first, second or third offense; felony or accident involved; blood alcohol level; refusing chemical testing; and what matters most to them (experience, price or a free consultation).
- **To ask you:** what the engine told the shopper to ask the business. In the same run: who will personally handle the case, what the total fee includes, and how many cases like this the attorney has tried.

Copy each question word for word and count its runs. Every question becomes a row in guide section 6, unless it's about something the client doesn't offer.

**(c) Kinds of sources cited.** Sort every cited link by kind, not by name:
- Licensing or regulatory records
- The businesses' own pages (bios, about pages, service pages)
- Award and rating sites
- Industry directories
- General directories and review sites
- Associations and certifying bodies
- News and press
- Official guidance, such as a government page

Count the runs for each kind. These are the places the client's facts should appear, so they feed the profiles table in guide section 7.

**(d) Kinds of facts repeated about named businesses.** Write down the kind of fact and drop the name. For example: "former prosecutor, with years", "law school and graduation year", "an award's name with its years", "outcomes the firm reports itself". This shows how much detail the engines repeat, which tells you how specific the client's facts need to be.

## When you can't run an engine

- **No browser:** give the user the prompts above, ask them to paste each run with its header details, then carry on.
- **Never stand in for an engine.** Don't answer the prompts yourself and log that as a run. Your own knowledge isn't an engine run, and a web search result isn't one either.
- **Nothing run at all:** write "AI research skipped." in the summary and in guide sections 5 and 6. Build the proof map from the client research alone. Section 6 can list questions found in the client's reviews and own words, labeled as coming from there.

## Using the results

- **Criteria are facts to go find, not claims to make.** For each one, look for the client's proof in the research. If you find none and the client probably has it, make it a sign-off sheet item with a drafted answer.
- **Criteria the client meets become questions.** The ones with public or confirmed proof can become guide 3.10 questions for readers with a default ("Who will actually be at your court date?"), answered with that proof. Never raise one the client can't visibly meet.
- **Leave out criteria the client can't meet.** The guide doesn't mention them, and the copy doesn't write around them.
- **Flag certain criteria for approval.** Criteria about results, ratings, comparisons or specialist titles go to the client for approval (SKILL.md, rule 12).
- **Re-run to test.** Repeat the same set after the client's facts are live on the site and profiles, then compare whether the engines repeat those facts. That's the test. We have no measured result from it yet.
